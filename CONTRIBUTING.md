# Правила работы в репозитории

## Ветки

- `main` — основная ветка, изменения только через Pull Request, прямой push запрещён
- Новая ветка на каждую задачу: `тип/номер-issue-кратко`
  - `feature/5-job-lifecycle` — новая функциональность
  - `fix/12-wrong-status` — исправление ошибки
  - `docs/3-requirements` — документация
  - `test/8-dispatcher-tests` — тесты
- Ветку удаляем после влития PR

## Коммиты

Формат: `тип: что сделано (#номер-issue)`

- `feat:` — новая функциональность
- `fix:` — исправление ошибки
- `docs:` — документация
- `test:` — тесты
- `refactor:` — изменение кода без изменения поведения
- `chore:` — настройка, зависимости, CI

Пример: `docs: сценарии создания и отмены Job (#3)`

## Pull Request

- Один PR — одна задача из Issues, в описании `Closes #номер`
- PR небольшой, чтобы его можно было проверить за 15 минут
- Автор назначает проверяющего по кругу:
  - Зернаев Роман (amorfix) проверяет Мордикова Артёма (Mavrussia)
  - Мордиков Артём проверяет Анисимова Михаила (mishany777)
  - Анисимов Михаил проверяет Зернаева Романа
- Если PR затрагивает чужую зону ответственности, владелец этой зоны добавляется вторым проверяющим
- Для влития нужен Approve проверяющего по кругу, а если назначен владелец зоны, то и его Approve
- После Approve PR вливает автор, способ — Squash and merge

## Review

- Проверяющий отвечает в течение суток
- Замечания по сути: ошибки, непонятные места, пропущенные случаи, вопросы
- Комментарии "ок" или "TEST" review не считаются
- Если есть замечания, ставим Request changes, после исправления — Approve

## Definition of Done

Задача считается сделанной, когда:

- выполнены критерии приёмки из issue
- PR одобрен другим участником, все замечания закрыты
- CI зелёный, новый код покрыт тестами, когда появятся тесты и CI
- документация и README обновлены, если изменение их касается
- PR влит в `main`, issue закрыт

## Роли и зоны ответственности

Каждый участник пишет код и делает review на каждой практике. Зона ответственности — это то, за что человек отвечает в первую очередь. Если чужой PR затрагивает его зону, он становится вторым проверяющим.
