# AutoCheck — сервис автопроверки учебных работ

Команда emotion: Зернаев Роман, Мордиков Артём, Анисимов Михаил.

## Какую проблему решает

Преподаватель курса получает десятки Pull Request с учебными работами. Формальную часть каждой работы приходится проверять вручную: все ли файлы на месте, заполнены ли разделы шаблона, не тронуты ли чужие папки, не слишком ли большой PR. Это долго, а студент узнаёт об ошибке только через несколько дней.

AutoCheck выполняет формальные проверки автоматически сразу после отправки работы и пишет результат комментарием в PR. Преподаватель тратит время только на содержание.

## Для кого

- **Студент** — отправляет работу через PR и сразу видит, что исправить
- **Преподаватель** — задаёт набор проверок для задания и видит итог по каждой работе
- **Клиент API** — GitHub Actions или скрипт, который ставит проверку автоматически

## Как устроено

Запрос на проверку → Проверка (Job) → Диспетчер → Реестр проверок → Исполнитель (Tool) → Результат (ToolResult)

1. Клиент отправляет `POST /checks`: репозиторий, номер PR, список проверок, ключ идемпотентности
2. Сервис создаёт Проверку в состоянии `queued`
3. Диспетчер берёт её в работу и по реестру находит исполнителя для каждой проверки
4. Исполнитель получает файлы PR через GitHub API и возвращает результат: пройдено или список проблем
5. Сервис сохраняет результаты, переводит Проверку в итоговое состояние и пишет комментарий в PR

## Что входит в систему

- HTTP API для постановки, просмотра и отмены проверок, контракт в OpenAPI
- Исполнители проверок: структура файлов, разделы шаблона, размер PR, стиль Markdown. Новая проверка добавляется без изменения диспетчера
- Хранение истории проверок и результатов: SQLite на прототипе, PostgreSQL в итоговой версии
- Адаптер GitHub API с timeout, повторными попытками и fake-сервером для тестов
- Автотесты и CI, логи с correlation ID, health check, запуск одной командой через Docker Compose

## Что точно не входит

- Запуск кода студентов: для этого нужна песочница, это вне рамок проекта
- Оценка содержания работы: это задача LLM во втором семестре
- Веб-интерфейс: результаты видны в комментарии PR и через API
- Учётные записи и роли пользователей: доступ к API по одному токену
- Другие платформы, кроме GitHub

## Шов для LLM

Во втором семестре появится ещё один исполнитель — LLM-рецензент. Он будет оценивать содержательную часть работы по критериям задания и возвращать результат в том же формате ToolResult. Диспетчер и API при этом не меняются.
