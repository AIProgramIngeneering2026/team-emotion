# ADR-0001. Один процесс вместо нескольких сервисов

- **Дата:** 2026-11-14
- **Статус:** принято

## Контекст и ограничения

- Команда из трёх человек, срок — один семестр, восемь контрольных точек
- Нагрузка небольшая: одна группа курса, десятки PR в неделю, пики перед сроками сдачи
- Курс не даёт баллов за количество сервисов и брокеры сообщений
- К практике 7 нужен запуск одной командой `docker compose up`

## Решение

AutoCheck — один процесс на Python: HTTP API, Worker, Dispatcher, Registry и Tool работают в нём. Отдельно запускается только СУБД. Внутри границы проведены через интерфейсы: ядро не импортирует FastAPI, SQLAlchemy и httpx.

## Рассмотренные альтернативы

| Вариант | Почему не выбрали |
|---|---|
| Отдельный сервис API и отдельный сервис Worker с брокером, например RabbitMQ | Ещё два контейнера и протокол между ними. Для нашей нагрузки выигрыша нет, сложнее запускать и отлаживать |
| Отдельный сервис на каждый Tool | Сетевые вызовы между своими компонентами, отдельный контракт на каждый. Tool работают миллисекунды, сеть стала бы самым медленным местом |

## Цена решения

- Нельзя масштабировать Worker отдельно от API
- Долгий Tool занимает ресурсы того же процесса, что и API
- Сбой процесса останавливает и приём запросов, и выполнение. Проверки в `running` после перезапуска уйдут в `error` по таймауту, см. [ADR-0002](0002-background-execution.md)

## Условия пересмотра

- Очередь Проверок регулярно ждёт дольше минуты
- Появляется тяжёлый Tool, например `llm_review` во втором семестре, которому нужна отдельная машина или GPU
- Сервис начинают использовать несколько курсов одновременно
