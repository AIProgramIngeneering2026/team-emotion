# ADR-0004. Один клиент API, без разделения Проверок по владельцам

- **Дата:** 2026-11-14
- **Статус:** принято

## Контекст и ограничения

- Сервисом пользуется один курс. Проверки ставит GitHub Actions курса, результаты смотрит преподаватель
- Учётные записи и роли пользователей вынесены за границы системы, см. раздел "Что точно не входит" в [README](../../README.md)
- Результаты Проверок и так видны всем участникам курса в комментариях PR

## Решение

Доступ к API по одному токену из переменной окружения `AUTOCHECK_API_TOKEN`. Все Проверки принадлежат одному клиенту, поле владельца не храним. `id` Проверки — случайный UUID v4, его нельзя подобрать перебором. Запрос несуществующего `id` даёт `404 check_not_found` без подробностей.

## Рассмотренные альтернативы

| Вариант | Почему не выбрали |
|---|---|
| Токен на каждого клиента, Проверка видна только создателю | Нужны учётные записи, выдача и отзыв токенов, проверка владельца в каждом запросе. Клиент у нас один |
| Вход через GitHub OAuth для студентов | Студентам не нужен API, результат они видят в PR |

## Цена решения

- Утечка токена даёт доступ ко всем Проверкам. Токен хранится только в секретах GitHub Actions и в `.env` сервера
- Нельзя отдать доступ к API второму курсу, не открыв ему Проверки первого

## Условия пересмотра

- Сервисом начинает пользоваться второй курс или вторая организация
- Через API начинают отдавать данные, которых нет в комментариях PR
